# Toast

Common application notification component. Owns the Base UI Toast compound exports, default external manager, and Toaster rendering. Preserve native manager, provider, portal, viewport, root, content, title, description, action, and close exports. Provider timeout defaults to 3000ms. The useToast hook takes no arguments; add(options) maps duration to native timeout and adds align metadata without altering caller data.

Alignment is top-center by default. Support top/bottom with logical start/center/end. Render one native viewport with independent flex groups per alignment; avoid multiple native viewports sharing a provider because Base UI stores a single viewport reference. Toasts in each group remain visible in normal flow, with newest nearest the corresponding viewport edge. Native provider limits, announcements, timers, focus, close and action behavior remain in Base UI. Render actions only when actionProps exists. Unknown/native-manager alignment falls back to top-center.

Keep styles in the named toast CSS Module layer, use canonical Tailwind @apply, semantic colors, logical horizontal positioning and em spacing. Stories and rendered tests cover positions, icons, names/descriptions, actions and close. Hook tests cover duration timers and independent alignment metadata.

All toast surfaces use the shared glass-interactive material with info, primary (default), success, error, and warning semantic color pairs. The native type is the only public option controlling color; matching status types supply the semantic color, while omitted, loading, or unknown types use primary. Preserve caller data. Do not expose a separate color option on add() or the compound Toast root; native updates to type must update the rendered color automatically. Titles, descriptions, icons and buttons inherit the matching foreground for contrast. Override the shared material's button-only scale/filter/cursor effects so notification text stays still. Verify all colors in light and dark themes, including contrast audits.
